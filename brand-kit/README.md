# Ozea Dental Clinic — brand & print kit

Press-ready files for Ozea Dental Clinic, Dr. Youssef Nasser. Everything here is
generated from two sources — `clinic.json` for the words and numbers, and the vector
masters in `../brand/logo/` for the artwork — so nothing in this folder is edited by
hand and nothing can drift from the website.

```bash
npm run build:brand-kit
```

Runs in about a minute. It refuses to run if the phone numbers, Instagram URL or Maps
link in `clinic.json` no longer match `src/lib/site.ts`, because a card with a dead
number is the one mistake a proof does not catch. The last thing it does is pack two
archives.

---

## The two archives

| File | Size | What it is |
| --- | --- | --- |
| `ozea-brand-kit.zip` | ~22 MB | The whole kit. Every logo variant as SVG, PNG and print raster; the PDFs; the previews with guides; the vCard and links; the typesetting fonts; and the self-contained HTML each PDF was rendered from. This is the one the clinic keeps. |
| `ozea-brand-kit-print-only.zip` | ~1.2 MB | The PDFs, the logo vectors and the preflight note. Small enough to email or send over WhatsApp. This is the one a printer gets. |

Each extracts into a single folder and carries a `MANIFEST.txt` listing every member
with its size, so the person at the other end can see whether the transfer arrived
whole. `npm run pack:brand-kit` re-packs without re-rendering, for when only a
hand-edited file changed.

## What to send a printer

| Piece | File | Trim | Bleed | Pages |
| --- | --- | --- | --- | --- |
| Business card | `print/ozea-business-card.pdf` | 90 × 50 mm | 3 mm | 2 (front, back) |
| Business card, ganged | `print/ozea-business-card-a4-10up.pdf` | 90 × 50 mm | 3 mm | 2 (10 up, duplex) |
| Prescription, English | `print/ozea-prescription-a5-en.pdf` | 148 × 210 mm | 3 mm | 1 |
| Prescription, Arabic | `print/ozea-prescription-a5-ar.pdf` | 148 × 210 mm | 3 mm | 1 |
| Letterhead | `print/ozea-letterhead-a4.pdf` | 210 × 297 mm | 3 mm | 1 |
| Brand guide | `print/ozea-brand-guide.pdf` | 210 × 297 mm | none | 3 |

Each piece also has a `*-proof-with-marks.pdf`: the same artwork on a larger sheet with
crop marks at the trim corners. Use it to approve the cut. **Do not send the proof to
press** — send the plain file.

Tell the printer three things:

1. **Cut to the TrimBox.** Every PDF carries an exact TrimBox and BleedBox. The page
   itself is a fraction of a millimetre off nominal, because of how the renderer rounds
   paper size; the TrimBox is exact and centred. Cut to it, not to the page edge.
2. **The files are RGB.** Convert with the house CMYK profile at output. The guide lists
   an un-profiled CMYK build per colour as a starting point — it is not a colour proof.
   The gold goes muddy if it is built as a screened yellow; it wants a solid build, or
   foil.
3. **Approve a physical proof before the run**, especially anything with the gold on it.

The QR codes carry the short link `https://wa.me/201069799460`, which opens the same
WhatsApp chat as the website's button but without the pre-filled opener. That is a print
decision, not a shortcut: with the message in the URL the code needs 49 modules, which at
13 mm on a card is 0.27 mm a module — under what a phone camera reads reliably on uncoated
stock. The short form needs 25 modules, 0.52 mm each. The build enforces a 0.3 mm floor and
refuses to render a code below it.

`print/PREFLIGHT.txt` is generated by reading the finished PDFs back: page count, sheet
and trim size in millimetres, how the glyphs are carried, and a raster-image count
(zero — the artwork is vector throughout). It is the file to forward if a printer asks
what is inside.

| Piece | Stock and finishing |
| --- | --- |

## Logos

`logos/svg/` — thirteen files, all cut from the same three masters:

| Shape | Inks | Use |
| --- | --- | --- |
| `ozea-mark-*` | `gold`, `ink`, `white`, `on-ink` | The medallion. Header badges, stamps, signage, foil dies. |
| `ozea-lockup-*` | `gold`, `ink`, `white`, `on-ink` | Medallion + engraved rule + OZEA + DENTAL CLINIC. Card front, covers, share cards. |
| `ozea-icon-*` | `gold`, `ink`, `white`, `on-ink` | The medallion with thickened linework, for small sizes: favicons, stamp dies, embroidery. |
| `ozea-mark-tile-ink` | — | Rounded ink tile. Profile pictures, stickers. |

`logos/png/` carries each of those at 256, 512, 1024, 2048 and 4096 px on a transparent
ground. `logos/print/` has the two shapes a supplier actually asks for at 60 mm wide,
300 and 600 dpi, as PNG and LZW TIFF with the density written into the file.

**Send the SVG whenever the supplier will take it.** A vector has no resolution to get
wrong, and it is what a foil or cutting die is made from.

Rules that matter, in full on page 2 of the brand guide:

- Clear space is one quarter of the medallion's diameter on all four sides.
- Minimum size: medallion 9 mm wide, stacked lockup 22 mm wide. Below that use the
  thickened `ozea-icon-*` master.
- Gold on ink, ink on paper, or white on ink. Never gold on a mid-tone.
- Never re-draw, re-trace, stretch, rotate, outline or shadow the artwork.

## Other files

- `data/ozea-dr-youssef-nasser.vcf` — vCard, so the card's data can be handed over
  without retyping it.
- `data/links.txt` — every link in one place: the short WhatsApp link the printed QR
  codes carry, the two message-bearing openers the website uses, Maps and Instagram.
- `preview/*.png` — every artboard at 4× with the trim (magenta) and safe-area (cyan)
  guides drawn on. For checking and approving. The guides exist only in the previews,
  never in a print PDF.
- `fonts/` — the single-weight Latin faces the pieces are typeset in. Fetched by
  `node scripts/brand-kit/fetch-print-fonts.mjs`; if the folder is missing the build
  falls back to the website's variable fonts and still produces every file.
- `build/` — the intermediate HTML the PDFs are rendered from. Self-contained: fonts
  and artwork are inlined, so one of these files opens and prints correctly on a machine
  that has never seen this repository. Not committed.

## Changing something

**A phone number, the address, the hours, the Instagram handle.** Edit `clinic.json`,
then `npm run build:brand-kit`. If the change is to a phone number, Instagram or Maps,
update `src/lib/site.ts` too — the build compares them and stops if they disagree.

**The registration number.** `clinic.json` carries `doctor.license: null`, and no
licence line is printed. Set it to the real number and the labelled line appears on both
prescription sheets, in both languages. It is left empty on purpose: `PRODUCT.md`
records that no credential has been supplied, and nothing in this kit invents one.

**The layout.** The artboards are in `scripts/brand-kit/artboards/`, one file per piece,
positioned in millimetres. `scripts/brand-kit/tokens.mjs` holds the palette, the trim
and bleed geometry and the reproduction floors.

**The artwork.** Redraw in `brand/logo/*.svg` and re-run. Every logo file, every raster
and every printed piece is cut from those masters, so they cannot fall out of step.

## Two things to know

**Type 3 fonts.** The renderer carries web-font glyphs as Type 3 fonts — each glyph an
embedded vector procedure — rather than embedding the TrueType file. It prints correctly
at any size and needs no font installed anywhere; what it costs is text you cannot select
or search inside the PDF, and a strict preflight profile may flag it. Headless Chrome
embeds a real TrueType font only for faces installed on the operating system, so if a
printer refuses Type 3: install Cinzel, Inter, Inter Tight and IBM Plex Sans Arabic (all
free, all on Google Fonts) and run the build again. Nothing in the layout moves.
`print/PREFLIGHT.txt` reports which mode each file actually came out in.

**Nothing here is a claim.** No credential, no statistic, no strapline, no before-and-after,
no patient imagery. `PRODUCT.md` records that none of those have been supplied or
verified, and a printed piece is the worst place to invent one — it outlives the website
and cannot be corrected after the run. What the pieces carry is checkable: a name, a
scope of practice, an address that resolves, two numbers that answer, an account that
exists.
